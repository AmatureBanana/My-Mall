# Domain Docs

本仓库采用 single-context 领域文档布局。

## 探索代码库前

- 阅读仓库根目录的 `GLOSSARY.md`。
- 阅读 `docs/adr/` 下与当前工作相关的架构决策记录。

文件不存在时直接继续。
术语和决策实际明确后，由 `/domain-modeling` 按需创建。

## 文件布局

- `GLOSSARY.md`：仓库统一的领域术语表。
- `docs/adr/`：仓库统一的架构决策记录目录。

## 使用统一术语

任务标题、重构建议、假设和测试名称中的领域概念，
使用术语表定义的名称。

遇到术语表尚未覆盖的概念时，
先判断是否符合项目已有语言；
确有缺口时记录为后续领域建模事项。

## 标明架构决策冲突

方案与现有 ADR 冲突时，
明确指出对应 ADR，并解释重新讨论该决策的理由。
