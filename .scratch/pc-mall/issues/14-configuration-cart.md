# 14: 合法配置整组入车与去重

**What to build:** 服务端复验整套配置并原子入车，单品和配置组并存，去重且汇总同SKU需求。

Blocked by: [11：图形输出、功率、空间与完整核心准入](11-compatibility-admission.md)，[13：单品购物车持久化与数量管理](13-single-item-cart.md)

Status: ready-for-agent

**规格依据：** [电脑智能选配与商城联动系统实施规格](../spec.md)，版本 1.0，2026-10-28；原报告、追踪矩阵及来源指纹见母规格。保留原需求基线，本票不改冻结规则或增加 P1/P2 范围。

**主责需求：** F02-17、F02-18、F05-07、F05-08、F05-09、F05-10、F05-11、F05-12、F05-13、F05-15、F05-16、F05-17

**范围与交接：** 合法配置整组原子入车、分组关系和聚合需求。

与普通单品共用购物车，但配置组不是整机SKU，不能被单品合并规则吞并。配置修改能力由15完成，本票先保护组内不可拆改。

## Acceptance criteria

- [ ] 登录用户主动提交真实商品配置，服务端重验完整性、F03核心通过、当前可售状态、价格和库存。
- [ ] 七类基础或合法八类配置可整组入车，每类仅一个销售SKU、一个单位；不完整或未知不得通过。
- [ ] 任一明细失败时整个配置组回滚，界面不显示部分成功组，不锁价或预占库存。
- [ ] 单品与配置组、多个不同配置组可共存，同SKU归属分别保留并汇总已有购物车需求。
- [ ] 完全相同类别/SKU/数量的配置去重，名称、来源和价格差异不绕过去重；重复请求不能多建组。
- [ ] 展示组及明细并支持整组删除；拒绝在购物车中拆组或单独更改组内数量。
- [ ] 验证第八项写入失败、重复并发入车、伪造通过字段、聚合缺货及游客拦截。
