# 08: 性能评分维护与可信样本数据

**What to build:** 管理可追溯CPU/GPU评分和固定映射，准备三场景可验证的真实硬件样本。

Blocked by: [05：后台商品与八类参数维护](05-catalog-administration.md)

Status: ready-for-agent

**规格依据：** [电脑智能选配与商城联动系统实施规格](../spec.md)，版本 1.0，2026-10-28；原报告、追踪矩阵及来源指纹见母规格。保留原需求基线，本票不改冻结规则或增加 P1/P2 范围。

**主责需求：** F07-15

**范围与交接：** F07 评分维护、固定版本参考及后续三场景数据前置。

这是可在后台操作和核验的数据管理闭环。先准备三场景可靠样本，规定性能测试规模在24补齐；不新增P1批量导入页面或在线公式编辑。

## Acceptance criteria

- [ ] ADMIN 可维护 CPU/GPU 有效评分数据及来源、基准版本、采样条件、原始值和映射版本。
- [ ] 采用固定版本 Blender 渲染参考，型号与变体匹配有依据；缺失、不可靠或混合口径数据不得补默认有效分。
- [ ] CPU 0/50/200/450/800、GPU 0/500/2000/4500/8000 分别映射到 0/25/50/75/100，相邻插值并封顶100。
- [ ] 容量口径与固定 RAM/SSD 评分节点一致，SSD 1TB=1000GB；原始单位可追溯。
- [ ] 提供足以验证办公核显、游戏独显及内容创作的真实候选，售价和库存明确为商城演示数据。
- [ ] 数据包记录来源、校验值与许可归因；评分变更影响后续读取并留痕，不能在线任意改冻结权重。
- [ ] 验证后台维护、缺评分处理、插值边界与版本稳定性；负面测试样本与正常商品分开。
