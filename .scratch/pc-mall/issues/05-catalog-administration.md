# 05: 后台商品与八类参数维护

**What to build:** 管理员维护商品草稿、专属参数和上下架；校验唯一性与上架条件并留存审计。

Blocked by: [02：商城分类、搜索与商品详情](02-product-catalog.md)，[03：注册登录、会话与后台准入](03-session-auth.md)

Status: ready-for-agent

**规格依据：** [电脑智能选配与商城联动系统实施规格](../spec.md)，版本 1.0，2026-10-28；原报告、追踪矩阵及来源指纹见母规格。保留原需求基线，本票不改冻结规则或增加 P1/P2 范围。

**主责需求：** F07-04、F07-05、F07-06、F07-07、F07-08、F07-09、F07-10、F07-26

**范围与交接：** F07 商品主数据、参数和基础审计；为后续管理功能提供复用能力。

本票首次落地共享后台表单与审计能力。后续用户、价格、库存、评分和订单管理复用它，不另建平行管理或认证系统。

## Acceptance criteria

- [ ] ADMIN 可分页筛选商品并查看详情，普通用户直接调用管理接口被拒绝。
- [ ] 新增八类商品默认 OFF_SALE，SKU 与商品 ID 唯一；SKU 和类别创建后不可变。
- [ ] 可维护名称、品牌、型号、描述、图片地址及八类专属参数，校验类型、集合语义和单位。
- [ ] 参数模型覆盖 F03 C01～C10 的完整所需字段，不以候选数据集缺字段缩减基线。
- [ ] 缺必要信息或适用参数时拒绝上架并指出原因；上下架不物理删除商品及历史关联。
- [ ] 关键参数及上下架变更记录操作者、对象、时间与变更内容，需要原子的变更与审计一起提交。
- [ ] 用管理页面、真实 MySQL 接口及错误注入验证新增、重复 SKU、编辑、上架拒绝和审计回滚。
