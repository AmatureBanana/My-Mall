# 18: 模拟支付与本人订单查询

**What to build:** 用户查询本人订单并在截止前模拟支付，支付幂等且不重复扣库存。

Blocked by: [16：单品原子下单与成交快照](16-single-item-order.md)

Status: ready-for-agent

**规格依据：** [电脑智能选配与商城联动系统实施规格](../spec.md)，版本 1.0，2026-10-28；原报告、追踪矩阵及来源指纹见母规格。保留原需求基线，本票不改冻结规则或增加 P1/P2 范围。

**主责需求：** F06-19、F06-20、F06-24

**范围与交接：** 本人订单读取和有效期内站内模拟支付。

本票必须已拒绝到期支付，即使自动扫描尚待19实现。F06-T21中的取消路径由19完成，此处只验证订单归属的共享边界。

## Acceptance criteria

- [ ] 用户可查看本人订单列表、详情、成交单价和分组；其他用户访问被拒绝，历史展示不联查覆盖快照。
- [ ] 仅订单所有者能对PENDING_PAYMENT且服务端now早于expiresAt的订单执行模拟支付。
- [ ] 支付按订单成交金额和状态处理，转PAID并记录必要时间/结果，不调用真实支付。
- [ ] 支付不第二次扣减可售库存，重复与并发请求不产生重复有效支付或库存副作用。
- [ ] 恰好到期或过期时支付被拒绝，不能因扫描尚未运行而放行；非法状态有明确反馈。
- [ ] 通过真实MySQL、可控时钟和浏览器验证正常支付、越权、重复提交、截止边界与查询隔离。
