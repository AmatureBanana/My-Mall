# 07: 价格与可售库存受控调整

**What to build:** 管理员修改现价、调整库存并记录原因，查询口径一致且不覆盖预占关系。

Blocked by: [05：后台商品与八类参数维护](05-catalog-administration.md)

Status: ready-for-agent

**规格依据：** [电脑智能选配与商城联动系统实施规格](../spec.md)，版本 1.0，2026-10-28；原报告、追踪矩阵及来源指纹见母规格。保留原需求基线，本票不改冻结规则或增加 P1/P2 范围。

**主责需求：** F07-11、F07-12、F07-13、F07-14、F07-25

**范围与交接：** 统一当前售价、可售库存及受控变更口径。

即使订单功能尚未建立，也要为预占与释放保留统一受控语义。未来订单必须复用本票能力；测试不得把参考项目字段机械当作本项目库存定义。

## Acceptance criteria

- [ ] ADMIN 可修改合法正数 CNY 售价，精确到两位小数，用户查询读取更新后的价格。
- [ ] 可查询并受控调整非负整数可售库存，填写原因；预占关系不能被直接覆盖。
- [ ] 库存变更采用事务、固定顺序行锁与条件保护，不产生负数或丢失并发调整。
- [ ] 价格及库存变更的操作者、原因与前后值可追溯，审计失败导致应原子处理的变更回滚。
- [ ] 当前商品与参数变更可被后续重验识别，历史成交快照不通过商品更新链路改写。
- [ ] 真实 MySQL 验证并发调整、非法金额、负库存和审计故障；页面展示最新结果。
