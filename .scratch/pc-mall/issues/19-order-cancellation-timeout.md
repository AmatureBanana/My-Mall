# 19: 主动取消、超时与库存只释放一次

**What to build:** 本人取消和每分钟到期扫描共用受控状态转换，覆盖支付竞态、截止边界和安全重试。

Blocked by: [18：模拟支付与本人订单查询](18-payment-order-history.md)

Status: ready-for-agent

**规格依据：** [电脑智能选配与商城联动系统实施规格](../spec.md)，版本 1.0，2026-10-28；原报告、追踪矩阵及来源指纹见母规格。保留原需求基线，本票不改冻结规则或增加 P1/P2 范围。

**主责需求：** F06-18、F06-21、F06-22

**范围与交接：** 待支付订单主动/超时取消和一次性库存恢复。

取消、支付和超时在同一受控状态与事务规则下竞争；释放失败要可安全重试，不能先永久改终态再丢失释放责任。

## Acceptance criteria

- [ ] 本人可取消仍为PENDING_PAYMENT的订单，非法操作者及PAID/COMPLETED等非法状态被拒绝。
- [ ] 每分钟扫描到期待支付订单，取消并记录TIMEOUT、时间及必要处理信息。
- [ ] 主动取消与扫描共用状态保护，订单预占库存只释放一次，不恢复原购物车。
- [ ] 支付与取消/超时竞争时最多一个合法结果；到期支付始终拒绝，已取消和已完成不可恢复。
- [ ] 订单状态与库存恢复一致提交，数据库或扫描故障可安全重试，不永久错误占用或多释放。
- [ ] 用户页面显示当前状态和取消结果，不将P1支付倒计时作为本票前置。
- [ ] 可控时钟和真实并发验证重复取消、扫描延迟、截止时刻、支付竞争及释放故障回滚。
